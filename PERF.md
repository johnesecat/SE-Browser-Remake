# Performance report

M0 remains **incomplete**. These are local spike observations, not iPhone results or acceptance passes. Measured 2026-11-07 in the Freebuff cloud workspace, Rust 1.99.1, Bevy 0.20.1, Trunk 0.22.1, `wasm-opt` version_131 `-Oz`. Brotli quality 11 and gzip level 9 were measured locally with Node 26.13.0. WebGL2 artifact includes the wall-time diagnostic and ACES camera correction; the WebGPU artifact was built while a subsequent lint-only source edit was being made.

The standalone WebGPU offscreen and canvas-clear tests did not use the Bevy scene. The canvas clear failed without Bevy, so the environment-map pipelines are not necessary to reproduce the external-instance error in this environment. The exact browser/driver cause remains unidentified. The storage-texture validation mismatch is a separate observed compatibility risk, not a proven cause of device loss. Chromium's [maintainers note](https://github.com/gpuweb/gpuweb/discussions/4676) that the external-instance message alone does not identify a cause. The cloud browser intermittently returned 503s or lost its connection during further isolation. The loader's Bevy update-loop signal is not proof that a frame has rendered. A synthetic `webglcontextlost` event displayed the reload error; an actual WebGL context loss was not tested. The fallback downloads a second renderer after a failed WebGPU attempt, so the first-load target needs separate measurement for that path. The overlay reports Bevy update-frame wall time and FPS, not GPU time, draw calls or memory. A renderer label describes the selected artifact, not independent backend verification. The first release build failed because Binaryen rejected bulk-memory instructions; the retry passed after explicitly enabling the relevant Wasm features. The release profile now uses `strip = "debuginfo"` so wasm-bindgen can inspect `target_features`; both optimized builds completed without the earlier missing-metadata warning and passed Node wasm validation. Forced WebGL2 reached its update loop in cloud Chrome, while forced WebGPU still lost its device. No pixels were inspected in this check. A conservative uncompressed 8 MB gate currently fails for both artifacts. Pages' actual negotiated encoding and cold first-load size remain unverified.
