# COLLATERAL — living engineering plan

Status: M0 incomplete. WebGL2 rendered in desktop Chrome; WebGPU lost its device there, with automatic fallback to the WebGL2 update loop observed. Both uncompressed builds exceed the conservative 8 MB gate. Pages and iPhone remain untested. See PERF.md. Nothing is accepted until the stated tests are actually run. This is a static, single-player Rust/Bevy game, not a medical simulator. All ballistics and injury are stylised.

## Product decisions and constraints

- Personal project; public GitHub repository/demo is authorized. Open-source licensing beyond that is not established. No service, account, backend, multiplayer, telemetry, or external runtime CDN.
- Minimum target is iPhone 15 on the requested iOS 27.2; 30 fps minimum remains a goal and 60 fps is a goal for appropriate newer hardware. iOS version availability and actual device performance are **not verified**. Gore defaults to off/opt-in because the question was unanswered.
- Touch only: no pointer lock, haptics, required fullscreen, hover, or orientation lock. Safe areas, `100dvh`, portrait/landscape and debounced `visualViewport` changes are required. Audio requires a first touch; iOS has no web Vibration API.
- Static GitHub Pages, correct repository subpath, same-origin assets, no custom response headers. Default to single-threaded wasm; no SharedArrayBuffer, no cross-origin isolation shim unless explicitly tested and enabled later.
- Hard budgets are targets until measured: first load ≤25 MB (M0 <8 MB), one wasm ≤12 MB Brotli, full install ≤60 MB, 45-minute session and phone thermal stability. GitHub Pages negotiates HTTP compression itself; `.br` and `.gz` files alone are not automatically served as compressed responses. Measure actual network bytes rather than claiming the precompressed file size as a network result.
- Simulation outcome is deterministic and resolved before playback. Ballistics, anatomy/damage, and camera director remain pure Rust; Bevy is a presentation shell. No cinematic failure, skip, or abort changes a resolved shot.
- Data drives weapons, anatomy, behaviours, camera tracks and tiers. No unlicensed assets; maintain file-level source, license, attribution, SHA-256 and validation ledger. Cache and pool allocations; single-threaded operation is a requirement.

## Stack / evidence

- **Rust 1.99.1**, `wasm32-unknown-unknown`, pinned in `rust-toolchain.toml`; [Rust releases](https://blog.rust-lang.org/releases/). Bevy 0.20.1 requires Rust ≥1.97.1 per its [published manifest](https://docs.rs/crate/bevy/0.20.1/source/Cargo.toml).
- **Bevy =0.20.1**, default features off. A small explicit 3D/web feature set is preferred; avoid `default_platform` because it pulls `webgl2` and `multi_threaded`. [Feature reference](https://docs.rs/crate/bevy/0.20.1/features). WebGPU and WebGL2 are distinct cargo builds: [Bevy states WebGPU overrides WebGL2](https://docs.rs/bevy/0.20.1/bevy/).
- **Trunk 0.22.1** with `wasm-bindgen --target web` internally and release `wasm-opt -Oz`, hashed artifacts, separately built renderer directories. [Trunk asset/build reference](https://trunkrs.dev/assets). Exact auxiliary tool versions must be recorded from the actual tool/build; do not assert pins or sizes that have not been built.
- **Ragdoll decision: Rapier**, not Avian. Candidate **bevy_rapier3d =0.37.0**, which [depends on Bevy 0.20](https://docs.rs/crate/bevy_rapier3d/0.37.0/source/Cargo.toml). [Generic joints expose position/velocity motors with stiffness and damping](https://docs.rs/bevy_rapier3d/0.37.0/bevy_rapier3d/dynamics/struct.GenericJoint.html). Actual articulation/joint limits, fixed stepping, wasm compatibility and motor stability must be tested at M6; this is a future dependency, not yet integrated.
- Version-pin future serde/RON, math, Blender, glTF tooling and other dependencies at the milestone that uses them, after verifying their APIs and compatibility. Avoid a speculative dependency graph.
- Bevy's 3D/WebGPU web path remains a risk, not proven on Safari. [WebGL2 depth-prepass/MSAA issue](https://github.com/bevyengine/bevy/issues/9711) and [WebGL2 storage-buffer limitation](https://github.com/bevyengine/bevy/issues/19469) are historical/open reports, not proof of a 0.20.1 regression. Avoid MSAA/unsupported GPU assumptions; test the pinned version on both actual paths.
- Original character not supplied; user requested sourcing. [Z-Anatomy](https://github.com/Z-Anatomy/Models-of-human-anatomy) is a candidate, **not an accepted asset**: its [license ledger](https://github.com/Z-Anatomy/Models-of-human-anatomy/blob/master/License.txt) also lists NC components, which cannot be assumed cleared. Vet individual provenance and exclude prohibited assets. If CC BY-SA anatomy is accepted, isolate it in `assets/anatomy/` with applicable license and attribution, identify BodyParts3D derivation and document share-alike obligations. A personal project does not itself grant a license.
- Euphoria is proprietary; the intended alternative is a behaviour-driven active ragdoll, not a reimplementation. All frame-rate, size, memory and realism goals are subject to measurement and may require scope/quality reduction. Device GPU timings and iOS memory accounting may not be available to browser JavaScript; report unavailable values, not fabricated ones.

## Milestone checklist (strict order)

- [ ] **M0 — platform spike:** Bevy 3D scene, 1,000 spinning cubes, explicitly identified separate WebGPU/WebGL2 binaries, loading screen, renderer probe/override, fallback and failure handling, `?diag=1`, viewport resize, Pages deployment pipeline, real size reporting and gates. Acceptance: working iPhone Safari URL, WebGPU ≥30 fps, fallback works, cold load <8 MB, CI deploys, rotation and background/foreground work. Desktop Chrome can establish preliminary progress; real iPhone status must remain unverified.
- [ ] **M1 — character:** first validate sourced model and publish a table of format/size/triangles/materials/textures; skinning, armature and every bone; pose, scale, axes; separate organ/bone meshes; eyes/teeth/tongue/hair/clothing, morphs and clips. No silently missing organs. Normalize canonical rig and orientation, split body/skeleton/organs, organ parent mapping, optimize LODs/meshopt/KTX2, generate anatomical data and ledger. Lit turntable and anatomy debug toggle. Accept only after geometry, licensing and on-device performance checks.
- [ ] **M2 — ballistics and anatomy:** weapon RON, 1 kHz deterministic drag/gravity/wind/Coriolis and zeroing; tissue energy/penetration, seed-based fractures, wound polyline, organ thresholds/effects, exit and collateral; debug damage HUD. Test 1,000 replays, energy accounting, tissue order and 100 first-hit predictions.
- [ ] **M3 — bullet cam:** resolve before replay; trigger/skip/abort rules, data-driven chase/pre-impact/return tracks, collision guards, time dilation and robust state machine. Test skip/abort at every beat and 50 consecutive cameras.
- [ ] **M4 — X-ray reveal:** dithered skin dissolve, ivory bone and distinct organ materials, max-eight hysteretic occlusion fading, mobile uber-pass/grade and phone-size readability; prove impact visibility.
- [ ] **M5 — wound/fracture:** build-time seeded bone fracture variants and hulls, choose by real channel, local separation/impulses and fragment limits; tissue channel/temporary cavity, organ states, entry/exit, blood, damage report. Measure busiest frame.
- [ ] **M6 — active ragdoll/IK/cloth:** anatomical rigid bodies, Rapier joint limits and PD motors, fixed 60 Hz bounded substeps, animation blends, IK/foot placement/look/weapon hold/recoil, injury and pain behaviours, guards and damping. Generate bounded XPBD garments from body cross-sections, prewarm and LOD. Prove 45 s / 10-corpse soak without NaNs, explosions or excessive velocity and validate cloth/injury behaviours.
- [ ] **M7 — game:** outdoor village/compound/ridge and clear collateral line, sourced or original licensed assets; time-sliced perception/utility AI, navigation, cover and squads; first-person weapons, range/wind/hold breath, score, touch UI/settings/calibration/credits. Prove playable 10-minute session on phone.
- [ ] **M8 — polish:** spatial/audio unlock, layered slow-motion sound, camera feel, transitions, accessible subtitles, service-worker versioning/offline caching, streamed assets and progress, thermal monitoring and dynamic resolution. Measure 10-minute frame times.
- [ ] **M9 — ship:** optimization, asset/license audit, size gates, all CI checks, desktop Chrome smoke, on-device QA checklist, 45-minute soak, README and measured `PERF.md`; validate published Pages from a clean phone. Unknowns remain explicitly documented.
